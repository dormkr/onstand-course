# Week 33: Take-homes and pairing interviews

**7–13 June 2027 · Block E · Outline**

## Why this week exists

Many music-tech and smaller companies use a take-home or a pairing session instead of (or as well as) algorithm rounds: Ableton's process, as reported by a candidate, included a take-home task and on-site programming exercises. A take-home is graded like a PR: scope control, tests, a clear README, and judgment about what *not* to build. You've written PRs to a rubric for 30 weeks; now do it under a deadline.

## Tasks (14 h)

1. **Two practice take-homes, each time-boxed to 4 hours**, then reviewed against the PR rubric (and by an engineer, if possible):
   - *Web audio:* "build a step sequencer with 8 steps and 4 sounds, tempo control, sample-accurate timing, and tests" (reuse your week-6 clock thinking).
   - *Data:* "given a MIDI file, output a practice report: tempo stability, note density per bar, the hardest passages by your own definition", with a README that explains the definition.
   Both must include: a README (how to run, decisions, what you'd do with more time), tests, and no unneeded features.
2. **Mock #5: pairing.** An engineer gives you an unfamiliar repo (or an issue in an open-source project) and you work on it together for 45 minutes, thinking aloud. This is weeks 1–2's skill under observation.
3. **Mock #6: behavioural,** using your week-30 STAR stories. Ask for feedback on specificity and length.

## Gate

- **w33.takehome:** both take-homes done in the time box and scored ≥ 4 on the PR rubric.
- **w33.mocks:** mocks #5 and #6 done, with written feedback.
